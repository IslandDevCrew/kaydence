Kaydence ASR selection persistence evidence
Date: 2026-07-08

Intent
- Make the first-run Local ASR picker selectable instead of display-only.
- Persist the selected ASR model id in a schema-versioned app-data settings.json.
- Keep React presentation-only: the frontend forwards the selection intent and
  Rust owns validation, storage, and the returned AppSnapshot.

Changed files
- apps/desktop/src-tauri/src/settings/mod.rs
  - Added UserSettingsFile with schema_version and selected_asr_model_id.
  - Added SettingsStore rooted at app-data/settings.json, with missing-file
    defaults, JSON validation, pretty JSON writes, and atomic temp-file rename.
  - Rejects empty selected_asr_model_id values.
- apps/desktop/src-tauri/src/lib.rs
  - Added select_asr_model Tauri command.
  - RuntimeSnapshot now stores a SettingsStore when app-data is available.
  - Startup applies a persisted ASR model selection after registry readiness
    refresh.
  - Selecting a model validates that it exists in backend-owned ASR candidates,
    saves it, updates selected flags, and returns the refreshed AppSnapshot.
  - Added tests for selecting, persistence reload, and unknown-model rejection.
- apps/desktop/src/App.tsx
  - Local ASR option buttons now invoke select_asr_model and render Rust's
    returned snapshot.
- ops/mission/state.json and docs/CODEX_SUPER_GOAL_PROMPT.md
  - Removed editable ASR selection persistence from the P1-P0-2 remaining-work
    list and recorded the new evidence.

Honest limits
- This does not download model artifacts.
- This does not replace registry TODO hashes/sources with reviewed published
  artifacts.
- This does not implement Parakeet/Whisper inference adapters.
- This does not provide WER or latency evidence for real ASR output.
- This persists the selected model id locally only; it does not sync settings
  across devices and does not hot-reload edits made directly to settings.json.
