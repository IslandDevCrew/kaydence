Kaydence evidence: macOS conservative clipboard fallback
Date: 2026-07-08

Intent
- Add the third macOS delivery rung: clipboard set + Command-V paste + restore.
- Keep the secure-field/no-target gate in front of clipboard delivery.
- Avoid destroying user clipboard data by refusing clipboard fallback when the current pasteboard advertises non-text types we cannot faithfully restore through pbcopy/pbpaste.
- Keep restore bounded with a 20 ms post-paste delay before restoring the original text clipboard snapshot.

Changed
- apps/desktop/src-tauri/src/inject/macos.rs
  - MacOsTextInjector::caps now advertises clipboard only when focused AX role is Editable and the current clipboard snapshot is restorable.
  - paste_clipboard re-checks focused AX role, snapshots text/empty pasteboards, writes dictated text with pbcopy, posts Command-V via CGEvent, then restores the prior text snapshot.
  - Added conservative clipboard type classification from `osascript -e 'clipboard info'`.
  - Added parser tests for empty, text-only, non-text, and mixed text/non-text pasteboards.

Honest limits
- This slice restores text-compatible or empty pasteboards only; mixed/non-text pasteboards are refused so user data is preserved.
- A future NSPasteboard backend should snapshot and restore all advertised pasteboard item types.
- Live app-matrix validation is still required to prove target apps consume the Command-V event before restore.
