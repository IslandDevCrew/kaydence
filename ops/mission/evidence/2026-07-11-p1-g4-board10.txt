## RED baseline

- The prior Setup route was a long block inside the shared `App.tsx` monolith.
- It did not preserve the locked Board 10 hierarchy as a dedicated view: no compact nine-step rail, source-order progress line, four-choice license/service comparison, or stable action footer.
- Deep model and permission proof existed, but it competed with the first-run journey instead of supporting it.

## Implementation

- Extracted `FirstRunView.tsx`, `FirstRunView.css`, and `FirstRunEvidence.css`; every extracted file remains below the 800-line view-file ceiling.
- Rebuilt the route in locked source order: app/OS header, nine setup steps, progress, backend next-step strip, six configuration controls, four license/service choices, pricing clarification, and footer action.
- Kept deep model, permission, timing, and proof detail in a keyboard-closeable, auto-focused Evidence dialog with Models, Permissions, and Proof tabs.
- Kept the implementation honest where the illustrative board is ahead of P1 reality:
  - Whisper-Ahead remains visibly disabled and labeled P3;
  - only Free is selectable; paid choices are informational until their owning flows exist;
  - desktop capability is one-time, while Harbor is optional hosted service and every service remains self-hostable;
  - model, permission, hotkey, timing, and first-dictation state come from Rust in the native app;
  - the primary action renders the backend-owned `next_step.action_label`;
  - non-host Windows/Linux selections are explicit reference lanes and disable host-only runtime actions.
- Fixed `dictation` and `complete` next-step handling so the primary action reaches the Dictate view instead of only showing a note.
