2. DEFECTS FOUND ON THIS HOST (pre-existing on main)                 VERIFIED
────────────────────────────────────────────────────────────────────────────
D1  inject::platform_injector() was UnimplementedInjector on Linux — the
    shipped app could never deliver text on Linux (uinput/AT-SPI existed only
    in the atspi-selftest binary).
D2  profiles::PlatformFrontmostAppDetector was UnknownFrontmostAppDetector on
    Linux → verify_focus_binding() holds every Linux delivery Held{FocusChanged}
    even if an injector worked.
D3  /dev/uinput is `crw------- root root` on stock Omarchy → the ADR-0013
    validated uinput path is unavailable without sudo + udev + relogin.
D4  The default hotkey cannot be registered on Linux at all:
      "Unable to register hotkey: Unknown scancode for key: AltRight"
    (tauri-plugin-global-shortcut / global-hotkey 0.8). On Wayland an X11 grab
    would anyway only see XWayland windows. Linux never had a working hotkey.
D5  Omarchy ships a dictation-binding contract (voxtype.lua: F9 press→start,
    release→stop) that Kaydence did not speak.

5.4 Unicode typing into a real focused Wayland client — run 1      PARTIAL
    scripts/linux-wayland-inject-proof.sh (foot, byte-exact readback):
      PASS ascii      43 chars   30 ms
      PASS latin1     43 chars   27 ms
      PASS cjk        16 chars   30 ms
      PASS rtl        15 chars   22 ms
      PASS combining   8 chars   26 ms
      PASS emoji      28 chars   33 ms
      FAIL multichunk 300 distinct CJK chars (2 keymaps of 247 keys)
    Root causes (both real product bugs, both fixed):
      (a) Hyprland matched its keybindings by translating the virtual
          keyboard's keycodes through the PHYSICAL keymap. Dropped slots were
          exactly evdev 67 99 113 114 115 116 140 161 162 163 164 165 190 191
          192 200 201 207 210 224 225 228 229 230 = F9, Print, Mute, Vol±,
          Power, Calculator, Eject, media, MicMute, Touchpad, Brightness,
          KbdBacklight — and the user's Omarchy binds FIRED.
          Observed side effects on the operator's session: 2 screenshots in
          ~/Pictures (19:09:31, 19:09:34), microphone left MUTED (not changed
          back by the agent — prior state unknown; operator informed),
          voxtype start+stop instant pair, volume/brightness down+up (net 0),
          touchpad toggle→on (ends on). No window left open.
          FIX: slots now use ONLY 48 evdev codes whose stock meaning is a
          plain printable key (xkb.rs SAFE_EVDEV_CODES); regression test pins
          the 24 codes above as never used. Verified: Omarchy has no
          unmodified binds on any printable key.
      (b) Re-uploading a keymap on the SAME virtual keyboard is not forwarded
          by Hyprland (client kept decoding chunk 2 with chunk 1's keymap).
          FIX: a fresh virtual keyboard per keymap chunk (renew_keyboard).
    Status: FIXED+UNIT-VERIFIED. Live re-run PENDING (see 5.5).
