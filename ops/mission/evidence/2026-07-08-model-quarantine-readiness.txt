Kaydence model checksum quarantine evidence
Date: 2026-07-08

Intent
- Enforce the model registry invariant that checksum mismatches quarantine the
  local artifact before any engine can load it.
- Keep the model verifier local and auditable; no network download surface was
  added in this slice.
- Surface the quarantine path through first-run readiness so a user/build agent
  can see why the model is blocked and where the suspect file moved.

Changed files
- apps/desktop/src-tauri/src/models/mod.rs
  - Added QUARANTINE_DIR_NAME = "quarantine".
  - verify_artifact now moves a mismatched artifact into
    models/quarantine/<filename>.<actual-hash-prefix>.bad before returning a
    ChecksumMismatch error.
  - Repeated mismatches use unique suffixes instead of overwriting earlier
    quarantined artifacts.
  - Added tests for quarantine movement and unique quarantine names.
- apps/desktop/src-tauri/src/lib.rs
  - First-run model status now reports "Checksum mismatch; quarantined at ..."
    for mismatched artifacts.
  - Added runtime snapshot coverage proving first-run readiness quarantines a
    mismatched model artifact and blocks it.
- ops/mission/state.json and docs/CODEX_SUPER_GOAL_PROMPT.md
  - Updated P1-P0-2 remaining work: quarantine is no longer open; download
    fetch/source replacement and real engine adapters remain.

Honest limits
- This does not download model artifacts.
- This does not replace registry TODO hashes or TODO sources with reviewed
  published artifacts.
- This does not implement Parakeet/Whisper inference adapters.
- This does not provide WER or latency evidence for real ASR output.
- If the app cannot rename the mismatched artifact, readiness still fails
  closed with a quarantine failure error; it does not load the artifact.
