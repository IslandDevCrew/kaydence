Kaydence evidence: finalized capture pipeline and injection spine
Date: 2026-07-08

Intent
- Move the live hotkey runtime beyond AudioPersisted-only history.
- Process finalized WAL captures through the existing VAD -> ASR -> cleanup event pipeline.
- Persist all downstream events before attempting delivery.
- Attempt injection only for committed text: CleanFinal segments when present, otherwise RawFinal segments.
- Preserve honesty while platform backends are incomplete: unavailable injection records Held/Failed events instead of pretending text was typed.

Changed
- apps/desktop/src-tauri/src/engine/mod.rs
  - Added EngineStack::empty for the current no-runtime-ASR-engine path.
- apps/desktop/src-tauri/src/pipeline/mod.rs
  - Added CaptureProcessor trait for runtime-owned finalized-capture processing.
  - Added default_runtime_pipeline using EnergyVad + default gate config + empty engine stack.
  - Changed ASR errors inside speech segments into SessionEvent::Failed { stage: Recognize } after AudioPersisted, keeping the session recoverable in history.
  - Added committed_text helper that prefers cleaned text and aggregates multi-segment finals.
- apps/desktop/src-tauri/src/inject/mod.rs
  - Added TextInjector::paste_clipboard default hook.
  - Added inject_committed_text orchestration: secure-field decision -> method selection -> backend call -> typed Injected/Held/Failed event.
  - Refreshed ADR-0013 wording to reflect Accepted status.
- apps/desktop/src-tauri/src/lib.rs
  - HotkeyRuntime now owns a CaptureProcessor, TextInjector, and the active SessionTarget selected at start.
  - FinalizeCapture now processes the WAL, persists pipeline events, extracts committed text, then records injection outcome.
  - Profile cleanup dial selected at capture start is applied to the finalized capture processor.
  - Short-tap discard still deletes the started session/event stream.
