Kaydence model download-plan evidence
Date: 2026-07-08

Intent
- Prepare the first-run model download flow without adding a network fetch
  surface yet.
- Make the registry prove that a missing model is actually downloadable before
  first-run readiness says "Download required."
- Keep the future fetcher bounded to a safe destination path, a verified
  expected sha256, and a normalized HTTPS mirror list.

Changed files
- apps/desktop/src-tauri/src/models/mod.rs
  - Added ModelDownloadPlan with model id, task, file, destination path,
    expected sha256, size, license metadata, and normalized sources.
  - Added ModelRegistry::download_plan and ModelEntry::download_plan.
  - Download plans reject placeholder checksums, empty/TODO sources, non-HTTPS
    sources, whitespace-bearing sources, unsafe artifact paths, and unknown ids.
  - Tests cover valid plan generation, duplicate mirror dedupe, placeholder
    checksum/source rejection, HTTPS-only source validation, and registry lookup.
- apps/desktop/src-tauri/src/lib.rs
  - Missing first-run artifacts now call download_plan before rendering a
    Missing state.
  - If a checksum is usable but sources are TODO/invalid, first-run readiness
    renders Blocked with "Download unavailable..." instead of implying a
    working download button exists.
  - Runtime snapshot tests cover both downloadable-missing and
    metadata-blocked-missing model states.
- ops/mission/state.json and docs/CODEX_SUPER_GOAL_PROMPT.md
  - Updated P1-P0-2 remaining work: planning is wired; network fetch/progress
    UI, reviewed artifacts, and real ASR adapters remain.
