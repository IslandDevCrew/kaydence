Kaydence evidence: macOS AX native text injector
Date: 2026-07-08

Intent
- Replace the macOS placeholder TextInjector with a real Accessibility-backed native insertion path.
- Detect focused macOS text controls through AX role/subrole and refuse secure fields before delivery.
- Use AXSelectedText for insertion so the backend inserts at the caret or replaces the current selection instead of overwriting AXValue for the whole field.
- Keep unsupported focus, missing Accessibility access, and non-text controls fail-closed as NoTarget / unavailable.

Changed
- apps/desktop/src-tauri/src/inject/mod.rs
  - Added macOS cfg module wiring and PlatformTextInjector alias.
  - platform_injector() now returns MacOsTextInjector on macOS and the placeholder on non-macOS platforms.
  - Updated the native insertion contract comment from destructive AXValue wording to selected-text insertion.
- apps/desktop/src-tauri/src/inject/macos.rs
  - Added dependency-free FFI bindings for ApplicationServices AXUIElement and CoreFoundation strings.
  - Added focused-element lookup via AXFocusedUIElement.
  - Added role/subrole classification for AXTextField, AXTextArea, AXComboBox, AXSearchField, and AXSecureTextField.
  - Added native insertion through AXUIElementSetAttributeValue(..., AXSelectedText, text).
  - Added capability probing with AXUIElementIsAttributeSettable for AXSelectedText.
  - Added pure unit tests for editable, secure, search, unsupported, and missing role classification.
