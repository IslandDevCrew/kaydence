DEFECT FOUND AND CLOSED IN CODE
- `asr-whisper` compiled whisper.cpp with no Metal feature. A requested GPU lane
  still reported `LocalGpu` even while whisper.cpp logged `no GPU found` and
  `using BLAS backend`.
- Added explicit `asr-whisper-metal = [asr-whisper, whisper-rs/metal]`.
- A GPU request without compiled acceleration now plans and reports `LocalCpu`.
- With acceleration compiled, the ordered stack is GPU then CPU fallback.
- `AsrEngine::warm_up` now loads the first viable model lane at startup and on
  idle-only model swaps. It does not load the fallback when the primary warms.
- A lane that fails warmup is retained as an explicit failed attempt but skipped
  during transcription, so its initialization cannot return to the hot path.
- Runtime `adapter_ready` remains false until real warmup succeeds. Warmup failure
  marks the runtime blocked and leaves the previous processor installed.
- Backend `ready_to_dictate`, first-run next-step ordering, and Screen Family 10
  now require `adapter_ready`; a checksum-valid model alone cannot show Ready or
  advance the user to permissions/first dictation.
- The real golden test measures warmup separately and enforces <=700 ms warm GPU
  inference or <=1200 ms warm CPU inference.

CANONICAL BUILD CONTRACT

  macOS builds `custom-protocol,asr-whisper-metal`; Windows and Linux build

- The launcher and PR matrix default `GGML_NATIVE=OFF`, preventing release and
  proof binaries from inheriting the hosted/build machine's instruction set.
  Reviewed architecture-specific release jobs can override it explicitly.
- The hosted Windows native proof compiles the same CPU adapter as the Windows
  release lane.

  proving the release launcher cannot silently return to a UI-only binary.
- A real optimized macOS build with
  `--features custom-protocol,asr-whisper-metal` completed successfully.
- After clearing the release-profile Whisper cache, a second optimized build
  completed with CMake proving `GGML_NATIVE:BOOL=OFF` and `GGML_METAL:BOOL=ON`.
  A fresh real-model test under the same portable setting named Apple M5 Pro +
  Metal, returned exact `Hello there`, warmed in 653 ms, and inferred in 59 ms.
- Because upstream `whisper-rs-sys` does not declare generic GGML/CMake env vars

  It cleans only the matching debug/release Whisper profile when that config

  unchanged reuse, explicit architecture change, and release-profile selection.

FIRST-RUN MODEL SCOPE
- First-run readiness now verifies the selected ASR artifact plus only support
  models explicitly marked `first_run_required`; it no longer requires every
  recommended ASR and an unused VAD model before setup can continue.
- The current runtime uses built-in `EnergyVad`, so the registry's Silero entry
  is not a hidden first-run dependency.
- A verified artifact is still insufficient by itself: adapter warmup must pass
  before `ready_to_dictate` or the setup step can advance to permissions.

COLD-START BOUNDARY
Before warmup wiring, a fresh Metal process once spent 5,772 ms in the first
transcription; about 4,968 ms was one-time embedded Metal library compilation and
load. That violated first-dictation latency. Model/backend initialization now runs
during app startup or an idle-only model swap and is excluded from release-to-final
latency. A warm process then measured 552 ms before this change; the explicit
warmup tests above measured 55-67 ms after initialization. Warmup duration has no
release-to-inject budget, but remains visible and must complete before readiness.
