2) SECURE-FIELD REFUSAL (non-negotiable #8 — the load-bearing invariant)
   Target: a WinForms TextBox with UseSystemPasswordChar (UIA IsPassword=true).
   $ uia-selftest --inject 4 "SHOULD NEVER APPEAR IN A PASSWORD FIELD"
   [focus] field kind: Secure
   [focus] caps: native=false keystroke=None clipboard=false
   [inject] SessionEvent: Held { reason: SecureField }
   Ground truth (the field's own TextChanged log): EMPTY — nothing was entered.
   Screenshot: 2026-07-09-windows-injection-secure-refusal.png
   Repeated a second time earlier in the session: identical Held{SecureField}, field empty.

3) KEYSTROKE FALLBACK (SendInput KEYEVENTF_UNICODE) into a classic Win32 Edit
   $ uia-selftest --synth 3 "aaa bbb ccc"
   Ground truth (TextChanged log): "aaa bbb ccc"  <- exact, incl. spaces + repeats.
   Also validated 20-char no-repeat string "abcdefghijklmnopqrst" -> exact (clipboard readback LEN=20).
   NOTE (honest, documented per inject/AGENTS.md app-compat matrix): the *new*
   Windows Notepad (WinUI/RichEditD2D) coalesces rapid synthetic KEYEVENTF_UNICODE
   events, so the pure keystroke rung dropped repeated chars THERE ("aaa bbb ccc"
   -> "aaa ccccccc"). The classic Edit control took it perfectly, and on Windows
   NATIVE is the PRIMARY path — Notepad receives native (run #1, clean). This is a
   target-specific fallback quirk, not a backend defect; logged for the matrix.

4) CLIPBOARD FALLBACK + RESTORE (Pitfall P2 — restore ALWAYS, <=200 ms)
   Pre-seeded the OS clipboard with "USER-CLIPBOARD-SENTINEL-42".
   $ uia-selftest --paste 3 "PASTED via clipboard rung OK"
   Ground truth (TextChanged log): "PASTED via clipboard rung OK"  <- injected.
   Clipboard AFTER injection: "USER-CLIPBOARD-SENTINEL-42"  <- RESTORED intact.
   Screenshot (earlier paste run): 2026-07-09-windows-injection-clipboard-paste.png (Notepad).

5) NO-TARGET GATE (bonus): when Notepad opened with focus on the tab strip (no

DEPENDENCY / AUDIT NOTE (critical decision path)
════════════════════════════════════════════════════════════════════════════
Added `windows` crate (Microsoft official) under
[target.'cfg(target_os = "windows")'.dependencies], version 0.61 — the version
ALREADY in Cargo.lock via tauri, so no new version enters the tree. Features are
minimal: Win32_Foundation, Win32_System_{Com,DataExchange,Memory,Threading},
Win32_UI_{Accessibility, Input_KeyboardAndMouse, WindowsAndMessaging}.
These are local OS input/COM/clipboard APIs — NOT a network surface. audit-network
stays green (no new call sites; nothing added to network-allowlist.json).
No elevation required; degrades to keystroke/clipboard if UIA is unavailable.
