Kaydence hotkey first-run readiness evidence
Date: 2026-07-08

Intent
- Make the frontend first-run setup panel reflect real backend runtime state
  instead of the default snapshot forever.
- Preserve the hotkey invariant that registration failures surface in onboarding
  and do not crash the app.
- Keep React presentation-only: readiness truth stays in Rust and is exposed
  through the existing Tauri app_snapshot command.

Changed files
- apps/desktop/src-tauri/src/lib.rs
  - Added managed RuntimeSnapshot state for app_snapshot.
  - Tauri setup now manages the snapshot before registering commands.
  - Global shortcut registration marks first_run.hotkey_registered on success.
  - Registration failure is captured as hotkey_registration_error and logged,
    while setup still returns Ok so the window can open.
  - Added unit tests for success and failure snapshot transitions.
- apps/desktop/src-tauri/src/settings/mod.rs
  - Added first_run.hotkey_registration_error: Option<String>.
  - Added serialization/readiness coverage for the error state.
- apps/desktop/src-tauri/src/hotkeys/mod.rs
  - Updated the module comment now that OS registration is wired through Tauri
    setup instead of future-gated.
- apps/desktop/src/App.tsx
  - First-run checklist now derives from AppSnapshot instead of static UI state.
  - Hotkey registration errors render as an Issue row.
  - Start action disables until model, microphone, input, and hotkey readiness
    are all true.
- apps/desktop/src/styles.css
  - Added compact issue and disabled-action styles for the setup panel.
- ops/mission/state.json and docs/CODEX_SUPER_GOAL_PROMPT.md
  - Updated stale hotkey notes so future sessions do not chase closed work.

Honest limits
- This proves the app-level snapshot contract and the graceful registration
  failure path. It does not prove OS-specific permission/conflict/rebind UX on
  macOS, Windows, or Linux.
- It does not close P1-P0-1 yet: toggle/rebind UI, live permission proof, the
  short-utterance suite, and latency/footprint gates remain.
- The first-run action is still a presentation entry point; model download,
  microphone permission prompts, and first dictation completion remain future
  P1-P0-8 work.
